# 书签同步器

通过 **WebDAV** 或 **S3 兼容对象存储**在多台设备之间同步 Chrome / Edge 书签。
书签以单个 JSON 文件明文存放在你自己的远端，每次内容变化保留一份历史快照。

没有服务器、没有账号、没有遥测。数据只在你的浏览器与你填写的那一个远端地址之间
流动。

核心设计约束是**弱网可靠**：在低带宽、高丢包、高延迟下，同步要么完整成功，要么
完全不生效，绝不产生「同步了一半」的中间状态导致书签丢失或重复。

## 功能

**三个显式操作**，语义互不重叠，不存在「自动帮你决定」的情况：

| 操作 | 行为 |
|---|---|
| **同步** | 双向三方合并（本地 / 远端 / 基线），冲突按字段级规则判定 |
| **上传** | 本地覆盖云端，云端独有条目会丢失，执行前弹确认并给出数量 |
| **下载** | 云端覆盖本地，本地独有条目会丢失，执行前弹确认并给出数量 |

其余功能：

- 同步两棵逻辑根：**书签栏**与**其他书签**（移动书签不参与同步）
- **字段级合并**：同一条书签，一台设备改标题、另一台改地址，两个改动都会保留
- **删除保护**：某一侧删除数量同时超过 10 条且超过该侧总数 10% 时中止，列出将被
  删除的条目并要求确认
- **历史版本**：每次内容发生实际变化时写一份完整快照，**永不自动删除**，可在设置页
  查看列表并下载任意一份
- **首次同步**：新设备接入时按 URL 与文件夹路径匹配去重合并，或选择单向覆盖
- **定时同步**与**浏览器启动时同步**（两者默认关闭）
- **条件写**：服务器支持 `If-Match` 时用 ETag 做乐观并发；不支持则降级为写后校验，
  并在设置页明确提示
- **弱网重试**：HTTP 层指数退避 + 抖动（最多 5 次），引擎层冲突重试（最多 3 轮）
- **运行日志**：最近 2000 条，可导出；凭据、`Authorization` 头、URL 中的 userinfo
  与查询串在写入前一律脱敏
- 界面文字全部经 `chrome.i18n`，内置简体中文；**零运行时依赖**，打包 37.6 KB

## 安装（Windows 编译）

尚未上架扩展商店，目前需自行编译并以开发者模式加载。全过程约两分钟。

### 前置要求

- **Node.js ≥ 20**（自带 npm）—— 到 [nodejs.org](https://nodejs.org/) 下载 LTS
  版安装即可。安装后**打开新的终端窗口**验证：

  ```bash
  node --version    # 应显示 v20.x 或更高
  npm --version
  ```

- **Git**（可选；也可以直接下载源码 ZIP 解压）
- Chrome 116+ 或 Edge 116+

不需要 Python、Visual Studio 或任何 C++ 工具链 —— 项目只用 esbuild，
`devDependencies` 里没有需要本地编译的原生模块。

### 编译步骤

在 PowerShell、CMD 或 Git Bash 中执行，三者都可以：

```bash
git clone https://github.com/luoLojic/bookmark-sync.git
cd bookmark-sync

npm install       # 安装开发依赖，约 1 分钟
npm run build     # 产物输出到 dist/
```

`npm run build` 会自动生成图标，并把 `manifest.json`、HTML、CSS、语言包一并放进
`dist/`。输出类似：

```
icons/icon16.png  178 B
...
  dist\background.js  54.2kb
  dist\options.js      9.2kb
  dist\popup.js        7.1kb
built → dist/
```

想在加载前先确认代码完好，可以跑一遍完整校验（约 30 秒）：

```bash
npm run verify    # typecheck + lint + 547 例测试 + 体积门禁
```

### 加载到浏览器

1. 打开 `chrome://extensions`（Edge 为 `edge://extensions`）
2. 打开**开发者模式**开关（Chrome 在右上角，Edge 在左下角）
3. 点**加载已解压的扩展程序**，选择项目下的 **`dist`** 文件夹
4. 建议点扩展栏的拼图图标，把「书签同步器」**固定**到工具栏

> **重要**：`dist` 文件夹的绝对路径决定了扩展 ID，而扩展 ID 决定了配置与基线存在
> 哪里。**加载之后不要移动或重命名这个文件夹**，否则配置、基线、映射表会全部丢失
> （等同于重装）。详见[使用建议](#使用建议)。

### 更新到新版本

```bash
git pull
npm run build
```

然后到 `chrome://extensions` 点该扩展卡片上的**刷新**按钮（↻）。只要 `dist` 路径
没变，配置与同步状态都不会丢。

### 卸载

在 `chrome://extensions` 点「移除」，浏览器会一并删除全部本地数据（配置、基线、
日志）。**远端已上传的数据不会被删除**，需要你自行在 WebDAV 服务器或对象存储上
清理。

## 使用方法

### 1. 填写远端配置

点工具栏图标 → 齿轮（⚙）打开设置页，先在「远端类型」里选 WebDAV 或 S3。

**WebDAV**

| 字段 | 说明 |
|---|---|
| 地址 | 服务器 WebDAV 根地址，如 `https://dav.example.com/dav/` |
| 用户名 / 密码 | WebDAV 账号。多数网盘要求使用「应用专用密码」而非登录密码 |
| 基础路径 | 扩展存放数据的目录，默认 `/bookmark-sync/`，不存在会自动创建 |

**S3 兼容对象存储**

| 字段 | 说明 |
|---|---|
| Endpoint | 如 `https://s3.us-east-1.amazonaws.com`，自建 MinIO 填自己的地址 |
| 区域 | 如 `us-east-1`。MinIO 等未启用区域概念的服务可填 `us-east-1` |
| Bucket | 存储桶名，需事先创建 |
| Access Key / Secret Key | 建议单独创建一个只对该 Bucket 有读写权限的密钥 |
| 路径前缀 | 桶内的目录前缀，默认 `bookmark-sync/` |
| 路径风格寻址 | **自建服务（MinIO 等）需勾选**；AWS S3 不勾选 |

已验证的 S3 服务商：**AWS S3、MinIO**。其他 S3 兼容服务（R2、COS、OSS 等）可以
填写，协议上应当可用，但未经实测。

### 2. 测试连接

填好后点**测试连接**。这一步做三件事：

1. **申请该地址的访问权限** —— 扩展默认不持有任何网站权限（manifest 里没有
   `*://*/*`），只在这时动态申请你填的那一个地址。浏览器会弹出授权提示，
   **必须允许**，否则无法同步。
2. 验证凭据是否正确。
3. **探测服务器是否支持条件写**（`If-Match`）。不支持时会降级为「写后校验」模式，
   设置页顶部出现黄色提示 —— 那种模式下多台设备同时提交存在极小概率的更新丢失
   窗口。单人使用可以忽略。

### 3. 第一次同步

点工具栏图标 → **同步**。因为本设备还没有基线，会弹出首次同步选择：

| 选项 | 适用场景 |
|---|---|
| **合并**（推荐） | 按 URL 与文件夹路径匹配去重后合并两边，会显示预估结果条数 |
| **以本地为准** | 用本地书签覆盖云端 |
| **以云端为准** | 用云端书签覆盖本地 |

**建议的多设备接入顺序**：在书签最全的那台设备上点一次**上传**，其余设备接入时
选**以云端为准**。这样每台设备的初始状态完全确定，不依赖 URL 匹配的猜测，也就不会
出现「同一条书签因为地址略有差异而变成两条」的情况。

### 4. 日常使用

- **同步**：双向合并，日常用这个。完成后弹窗底部显示「新增 / 更新 / 移动 / 删除」
  的条数，无变化时显示「无变化」且不产生任何写流量。
- **上传 / 下载**：单向覆盖，用于修正某一侧的错误状态。两者都会先弹确认，
  明确告知有多少条目将丢失。
- **取消**：同步进行中可以点取消。在唯一的原子提交点（`PUT bookmarks`）之前取消
  完全无副作用；该点之后不再响应取消，同步会走完。

### 5. 定时同步

设置页「同步」分组可开启：

- **定时同步**：默认关闭，开启后默认间隔 30 分钟。由 `chrome.alarms` 驱动，
  浏览器关闭期间不执行，下次启动后按计划继续。
- **浏览器启动时同步**：默认关闭。

同一处还可以调整**超时**（默认 30 秒）、**最大重试次数**（默认 5 次）、
**删除保护阈值**（默认 10 条 / 10%）与是否**压缩**（默认开启，远端文件为
`.json.gz`）。

书签变更**不会**触发同步 —— 这是刻意的：拖动书签会产生大量连续事件，事件驱动会
导致同步风暴。

顺便建议在「设备」分组填一个**设备名**（如「家里台式机」）。它只写入历史快照的
信封字段，用途是让你在历史列表里认出每份快照来自哪台设备。

### 6. 历史版本

设置页「历史版本」列出远端 `history/` 下的全部快照，显示写入时间、来源设备名、
条目数与大小，可下载任意一份 JSON。列表读的是 `history/index.json`，不依赖目录
列举，所以在不支持列目录的 WebDAV 上同样可用。

**历史永不自动删除** —— 它是误删后唯一的兜底。设置页显示总数与估算占用，
由你自行判断是否手动清理（在服务器上直接删文件即可，之后点「刷新索引」）。

### 7. 日志与重置

- **导出日志**：导出最近 2000 条运行日志。凭据、`Authorization` 头、URL 中的
  userinfo 与查询串都已脱敏为 `***`，可以安全贴给别人看。
- **重置同步状态**：清空基线，保留 ID 映射与配置。下次同步会被当作首次同步。
- **完全重置**：清空基线、ID 映射与全部配置（含远端地址与凭据）。

两者都需要**二次确认**，且都**不会**删除远端数据。

## 使用建议

**把 `dist` 放在一个固定不动的路径。** 以开发者模式加载的扩展，其 ID 由文件夹
绝对路径算出；而 `chrome.storage.local` 按扩展 ID 隔离。移动或重命名文件夹会让
ID 变化，等同于全新安装：配置、基线、映射表、日志全部消失，需要重填凭据，且下次
同步会被判定为首次同步。建议放在 `D:\tools\bookmark-sync\dist` 这类不会再整理的
位置。若希望换路径也保持同一身份，可以在 `src/manifest.json` 里加一个固定的 `key`
字段把扩展 ID 钉死（当前未设置）。

**先备份一次书签。** 浏览器书签管理器 → 右上角三点 → 导出书签到 HTML。第一次
跑通之前留一份，代价极小。

**S3 用单独的最小权限密钥。** 不要用主账号密钥。只授予目标 Bucket 的
`GetObject` / `PutObject` / `ListBucket` 即可。

**WebDAV 优先用应用专用密码。** 多数网盘支持为单个应用生成独立密码，
可随时吊销，不影响主账号。

**凭据在本地是明文存储的。** 浏览器扩展没有安全的密钥保管处，加密所需的密钥
必须存在同一个地方，能读到密文的攻击者同样能读到密钥。真正的边界是浏览器配置
目录的文件系统权限。这是明确的取舍，详见 [PRIVACY.md](./PRIVACY.md)。

**多设备并发编辑时，同步频率宁高勿低。** 两台设备各自积累大量改动再同步，
虽然合并逻辑能正确处理，但删除保护更容易被触发，需要人工确认。

**注意历史占用的增长。** 每次内容变化写一份完整快照（900 条书签约 15 KB gzip）。
每天变动几次的话，一年约几十 MB。定期看一眼设置页显示的估算占用。

## 故障排查

### 设置页 / 弹窗打不开或一片空白

先到 `chrome://extensions` 看该扩展卡片有没有红色的「错误」按钮，点开看详情。
若是刚 `git pull` 之后出现，多半是没重新 `npm run build`，或者没点卡片上的刷新
按钮。`dist` 目录被移动过也会导致加载失败。

### 「未获得该地址的访问授权，无法同步」

扩展默认不持有任何网站权限，需要在**测试连接**时授权。回设置页点一次测试连接，
在浏览器弹出的提示里选择允许。如果你之前误点了拒绝，可以在
`chrome://extensions` → 该扩展 → 「详细信息」→「网站权限」里手动添加。

**换了远端地址后必须重新测试连接** —— 权限是按地址授予的，新地址没有授权。

### 「认证失败，请检查用户名与密码」

- WebDAV：确认用的是应用专用密码而不是登录密码；确认地址是 WebDAV 端点而不是
  网页版地址（前者通常带 `/dav`、`/webdav` 之类的路径）。
- S3：确认 Access Key 与 Secret Key 没有多余空格；确认密钥对该 Bucket 有权限；
  确认**区域**填对了 —— 区域不匹配在部分服务上表现为签名错误而非 404。

### 「远端路径不存在」

远端返回 404。WebDAV 下扩展会**逐级创建**基础路径的每一层目录（含 `history/`），
所以正常情况不该出现 —— 出现说明地址本身不对：确认填的是 WebDAV 端点而不是网页版
地址，且路径大小写与服务器一致。S3 不涉及目录创建，但要确认 **Bucket 已经存在**，
扩展不会自动建桶。

### 「网络错误」/「请求超时」

先在浏览器里直接打开远端地址确认可达。若服务在境外或网络较差，到设置页把
**超时**（默认 30 秒）调大，把**最大重试次数**（默认 5 次）调高。这两个错误都属于
瞬时错误，**不会**清除任何本地状态，重试是安全的。

### 「服务器错误，请稍后重试」

远端返回 5xx 或 429。扩展已自动重试（指数退避 + 抖动，最多 5 次）仍未成功。
稍后再试；若持续出现，检查服务端日志或配额限制。

### 「其他设备正在频繁提交，请稍后重试」

引擎的冲突重试轮次（3 轮）用尽 —— 说明每次读取后提交时，远端都已被别的设备改过。
多台设备定时同步的间隔撞在一起时可能出现。把各设备的定时间隔错开即可。

### 「写后校验未通过，本次同步未生效，请重试」

服务器不支持条件写、已降级为写后校验模式，而校验发现写入的内容与预期不符
（可能是并发写覆盖，也可能是传输截断）。本次同步**未生效**，直接重试。频繁出现
说明该服务器的一致性较差，考虑换一个支持 `If-Match` 的服务。

### 「远端数据格式无法解析」

远端 `bookmarks.json.gz` 损坏或被其他程序改写过。可以在设置页的历史版本里下载一份
正常的快照检查内容；确认本地书签是正确的之后，用一次**上传**覆盖远端即可修复。

### 「远端数据由更高版本的扩展写入」

另一台设备上的扩展版本更高。升级本机扩展到相同版本。这是唯一一种允许清除本地
基线的错误情形。

### 「删除保护已触发」

本次同步将删除的条目数同时超过 10 条与该侧总数的 10%。弹窗会列出将被删除的条目
（最多列若干条，其余显示剩余数量）。**看清楚再确认** —— 这个机制正是为了拦住
「另一台设备意外清空了书签，然后把清空同步过来」。

若确认是误删导致的，不要确认删除：改用设置页历史版本下载最近一份正常快照，
或者在书签正常的那台设备上点**上传**。

### 「已有同步正在进行」

上一次同步还没结束。等它完成，或点取消。若是浏览器强杀 Service Worker 留下的
僵死状态，锁会在 **10 分钟**后被判定为过期并自动放行（NFR-8 的僵死检测）。

### 同步完成但书签顺序和另一台设备不同

顺序采用三方判定：只有真正调整过顺序的那一侧会作为骨架，两侧都调过时以正在同步
的这一侧为准。所以「先同步的一方顺序胜出，另一方的重排在下次同步时被覆盖」是
预期行为。单纯新增或删除条目不算重排。

### 收集诊断信息

设置页 → **导出日志**。日志已脱敏，含每一步的阶段名与耗时，是排查的第一手材料。

## 常见问题

### 能同步书签图标（favicon）吗？

不能，而且不需要。`chrome.bookmarks` 的书签节点只有标题、URL、父节点和位置四类
信息，图标不是书签数据的一部分。浏览器显示的图标来自它自己按 URL 索引的本地
favicon 缓存，访问站点时抓取。所以同步之后新设备上的图标会**自己出现**，只是
刚同步完可能先显示空白或地球图标。

真要「同步图标」，扩展得逐个访问你所有书签指向的站点去抓 favicon（相当于把书签
列表泄露给这些站点，体积也会从 15 KB 涨到几 MB），而且没有任何 API 能把图标
**写回**浏览器缓存 —— 抓来了也装不进去。

### 我只改了一条书签的标题（或地址），同步时会怎样？

条目身份由扩展分配的稳定 ID 认定，**不靠 URL 认**，所以改地址是一次「更新」，
不会变成「删掉旧的 + 新建一条」。三个字段（标题 / 地址 / 所在文件夹）各自独立
做三方判定：

| 情况 | 结果 |
|---|---|
| 只有一侧改了标题 | 标题更新，地址不变 |
| 只有一侧改了地址 | 地址更新，标题不变 |
| A 改标题、B 改地址（同一条） | **两个改动都保留** |
| A、B 都把标题改成了不同的值 | 正在同步的这一侧胜出并覆盖远端 |
| 一侧删除、另一侧修改 | 修改优先，条目保留 |

改动会让内容哈希变化，因此这次同步会往 `history/` 写一份快照。

**一个边界情况**：以上都建立在两台设备之间已有过一次成功同步（存在基线）之上。
若是**新设备第一次同步**，匹配靠的是 URL 与文件夹路径 —— 此时如果你在 A 上改过
某条书签的地址而 B 还是旧地址，两边匹配不上，合并后会同时保留两条，看起来像重复。
改标题不受影响（匹配键里不含标题）。这也是[前面建议](#3-第一次同步)「首次接入
用上传 / 以云端为准，而不是依赖合并」的原因。

### 能打包成 `.crx` 吗？和加载解压文件夹比有什么区别？

先纠正一个常见误解：**zip 不能直接拖进浏览器**。Chrome / Edge 只接受「加载已解压
的扩展程序」并选择一个文件夹。`npm run zip` 产出的 `release/bookmark-sync.zip`
用途是上传到应用商店，不是本地安装用的。

`.crx` 确实能生成（`chrome://extensions` 有「打包扩展程序」按钮，产出 `.crx` 与
`.pem` 私钥），但**装不上**：自 2014 年起 Chrome 与 Edge 在 Windows / macOS
稳定版上屏蔽非商店来源的 crx 安装，拖进去会提示「只能通过 Chrome 网上应用店添加」
或装上后立即被禁用。要绕开只有企业策略（`ExtensionInstallForcelist` /
`ExtensionInstallAllowlist` 配合自建 `update_url`）一条路。所以对个人自用，
crx 没有实际收益。

| | 加载已解压（当前方式） | 上架商店 |
|---|---|---|
| 扩展 ID | 由文件夹路径算出，**移动文件夹即变** | 固定 |
| 数据存续 | 路径一变，配置 / 基线全丢 | 稳定 |
| 开发者模式 | 必须常开，浏览器会有相应提示 | 不需要 |
| 自动更新 | 无，需 `npm run build` + 手动刷新 | 有 |
| 文件夹 | 必须一直留在原处，删掉即失效 | 无所谓 |
| 代价 | 无 | Chrome 一次性 5 美元开发者费 + 审核 |

自己几台设备用就继续加载已解压，但**务必把 `dist` 放在固定路径**；想要 ID 稳定
可以给 manifest 加 `key` 字段。上架商店可以选「不公开列出」，不必真的公开发布。

顺带提醒：若你自己打包过 crx，生成的 `.pem` 是**签名私钥**，泄露后他人即可签出被
浏览器视为「同一扩展」的包。仓库的 `.gitignore` 已经忽略 `*.pem` 与 `*.crx`。

### 支持 Firefox 吗？

不支持。项目基于 Manifest V3 与 `chrome.*` API，Firefox 的实现差异较大。
见[不做的事](#不做的事)。

### 移动书签为什么不同步？

移动书签根（`mobile_____`）在桌面浏览器上不可见也无法写入，参与同步只会造成
两边永久不一致。只同步书签栏与其他书签两棵逻辑根。

### 会上传我的浏览历史或标签页吗？

不会。扩展只申请 `bookmarks`、`storage`、`alarms` 三项权限，加上你填写的那一个
远端地址的动态权限。没有遥测、没有统计、没有崩溃上报、没有更新检查。
详见 [PRIVACY.md](./PRIVACY.md)。

## 远端数据布局

```
<基础路径>/
  bookmarks.json.gz         当前状态，所有设备读写这一个文件
  history/
    index.json              历史索引（设置页读它，不依赖目录列举）
    v000123-2026-07-28T10-30-00-000Z.json.gz
    ...
```

单个 JSON 明文存放（未加密），你可以随时直接下载查看或用别的工具处理。
900 条书签 / 120 个文件夹的实测大小：明文约 174 KB，gzip 后约 15 KB。

## 可靠性设计

四条不变量贯穿整个实现，测试逐条对照：

| 不变量 | 内容 |
|---|---|
| INV-1 | 基线只在远端提交成功后持久化。全项目只有一处写基线 |
| INV-2 | GUID 映射可增量持久化、只增不减，条目创建后立即落盘 |
| INV-3 | 瞬时错误不清除任何本地状态 |
| INV-4 | 中断后必须收敛，不做断点续传 |

提交协议九步，顺序不可调整。`PUT bookmarks` 是唯一的原子提交点：它之前的一切都
可以安全重来、可以取消；它成功之后同步即算成功，不再中止。

两层重试互不混淆：HTTP 层重试网络抖动（指数退避 + 抖动，最多 5 次），引擎层重试
逻辑冲突（412 或写后校验失败时整体回到读取阶段，最多 3 轮）。

### 分层

依赖只能自上而下，由 ESLint 静态强制：

```
ui/            只渲染与收发消息，不含同步逻辑
engine/        唯一决定副作用顺序的地方
domain/        纯函数：树模型、diff、合并、计划、删除保护
remote/        RemoteStore 抽象 + WebDAV / S3 transport
platform/      chrome.bookmarks、fetch、storage、crypto
shared/        错误、日志、配置、类型
```

`domain/` 内不得出现 `chrome.*`、`fetch`、`Date.now()`、`Math.random()`、
`crypto.*` —— 时间与随机数由调用方注入。这条由 ESLint 规则拦住。

### 测试策略

- **表驱动单测**覆盖合并判定矩阵的每一行
- **属性测试**（fast-check）验证代数性质：幂等、同值收敛、
  `apply(plan(a,b), a) = b`、计划有序、双设备交替同步收敛
- **崩溃注入矩阵**：9 个崩溃点 × 3 种改动方向 = 27 例，判定统一为
  「崩溃后重跑一次，结果收敛且无丢失无重复」
- **弱网注入**：可播种的假远端支持延迟、丢包、429/5xx、响应体截断、并发写
- **脱敏审计**：跑一次真实同步，逐项搜索日志里是否出现凭据
- **静态契约**：`hidden` 属性不被 `display` 规则压过、脚本引用的 id 必存在、
  manifest 引用的文件必有构建来源、声明的权限必被代码使用 —— 这类「只在浏览器
  加载那一刻才成立」的约束，逻辑测试看不见，单独固化

零运行时依赖。devDependencies 只有 esbuild / vitest / fast-check / typescript /
eslint。
