# 书签同步器

通过 WebDAV 或 S3 兼容对象存储在多台设备之间同步 Chrome / Edge 书签。书签以单个
JSON 文件明文存放，每次内容变化保留一份历史快照。

核心设计约束是**弱网可靠**：低带宽、高丢包、高延迟下，同步要么完整成功，要么完全
不生效，绝不产生「一半同步完」的中间状态导致书签丢失或重复。

## 功能

- **三个显式操作**：同步（双向合并）、上传（本地覆盖云端）、下载（云端覆盖本地）
- 同步两棵逻辑根：书签栏、其他书签（移动书签不同步）
- **删除保护**：一侧删除同时超过 10 条且超过该侧总数 10% 时中止并要求确认
- **历史版本**：每次内容变化写一份完整快照，永不自动删除，可在设置页查看与下载
- **首次同步**：新设备接入时按 URL 与路径匹配去重，或选择单向覆盖
- 定时同步与浏览器启动时同步（默认关闭）
- 界面文字全部经 `chrome.i18n`，内置简体中文

## 安装（开发者模式）

```bash
npm install
npm run build      # 产物在 dist/
```

浏览器打开 `chrome://extensions` → 打开「开发者模式」→「加载已解压的扩展程序」→
选择 `dist/` 目录。

## 配置

点击工具栏图标 → 齿轮 → 设置页：

**WebDAV**：填写地址、用户名、密码、基础路径（默认 `/bookmark-sync/`）。
**S3**：填写 Endpoint、区域、Bucket、Access Key、Secret Key、路径前缀。
自建服务（MinIO 等）需勾选「路径风格寻址」。

填好后点「测试连接」。这一步会申请该地址的访问权限（扩展默认不持有任何网站权限），
并探测服务器是否支持条件写（`If-Match`）。不支持时会降级为写后校验模式，设置页会
明确提示 —— 那种模式下多设备同时提交存在极小概率的更新丢失窗口。

已验证的 S3 服务商：AWS S3、MinIO。其他 S3 兼容服务可以填写，但未经验证。

## 远端数据布局

```
<基础路径>/
  bookmarks.json.gz         当前状态，所有设备读写这一个文件
  history/
    index.json              历史索引（设置页读它，不依赖目录列举）
    v000123-2026-07-28T10-30-00-000Z.json.gz
    ...
```

## 可靠性设计

四条不变量贯穿整个实现，测试逐条对照：

| 不变量 | 内容 |
|---|---|
| INV-1 | 基线只在远端提交成功后持久化。全项目只有一处写基线 |
| INV-2 | GUID 映射可增量持久化、只增不减，条目创建后立即落盘 |
| INV-3 | 瞬时错误不清除任何本地状态 |
| INV-4 | 中断后必须收敛，不做断点续传 |

提交协议九步，顺序不可调整。`PUT bookmarks` 是唯一的原子提交点：它之前的一切都
可以安全重来、可以取消；它成功之后同步即算成功，不再中止。

两层重试互不混淆：HTTP 层重试网络抖动（指数退避 + 抖动，最多 5 次），引擎层重试
逻辑冲突（412 或写后校验失败时整体回到读取阶段，最多 3 轮）。

## 开发

```bash
npm run typecheck   # TypeScript strict（含 noUncheckedIndexedAccess）
npm run lint        # 含分层依赖与 domain 纯度的静态强制
npm test            # 单元 + 属性 + 集成
npm run coverage    # domain 层门槛：行 ≥ 95%、分支 ≥ 90%
npm run size        # 打包体积门禁 < 200 KB
npm run verify      # 以上全部
```

### 分层

依赖只能自上而下，由 ESLint 静态强制：

```
ui/            只渲染与收发消息，不含同步逻辑
engine/        唯一决定副作用顺序的地方
domain/        纯函数：树模型、diff、合并、计划、删除保护
remote/        RemoteStore 抽象 + WebDAV / S3 transport
platform/      chrome.bookmarks、fetch、storage、crypto
shared/        错误、日志、配置、类型
```

`domain/` 内不得出现 `chrome.*`、`fetch`、`Date.now()`、`Math.random()`、
`crypto.*` —— 时间与随机数由调用方注入。这条由 ESLint 规则拦住。

### 测试策略

- **表驱动单测**覆盖合并判定矩阵的每一行
- **属性测试**（fast-check）验证代数性质：幂等、同值收敛、
  `apply(plan(a,b), a) = b`、计划有序、双设备交替同步收敛
- **崩溃注入矩阵**：9 个崩溃点 × 3 种改动方向 = 27 例，判定统一为
  「崩溃后重跑一次，结果收敛且无丢失无重复」
- **弱网注入**：可播种的假远端支持延迟、丢包、429/5xx、响应体截断、并发写
- **脱敏审计**：跑一次真实同步，逐项搜索日志里是否出现凭据

零运行时依赖。devDependencies 只有 esbuild / vitest / fast-check / typescript /
eslint。

## 不做的事

端到端加密、移动端、Firefox、标签页同步、移动书签根、API 型后端
（Nextcloud Bookmarks 等）、真正的 git 客户端、一键回滚、断点续传、
书签变更事件触发同步、favicon / 描述 / 标签同步。

理由见需求文档第 11 节。
